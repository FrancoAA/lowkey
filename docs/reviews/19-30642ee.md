# Review 19 — uncommitted work on top of 30642ee (MCP server for AI agents)

`lowkey --mcp`: an MCP server over stdio (read tools, transcribe_file, recording_status, and
start/stop_meeting behind Settings → AI agents), the Settings → AI agents tab, README.
Reviewer: DeepSeek V4.1 Flash (`opencode/deepseek-v4.1-flash`, variant high), read-only via
T3 Code `delegate_task`, told never to run the app, Hyprland, pactl, audio commands or agent CLIs.
Verdict: "No blocker. The design is sound: the server only reads (meeting ids are validated
before any path is built), the recording switch is enforced twice, `--transcribe` output is
byte-identical, and the protocol surface is correct for 2024-11-05 → 2025-11-25."

| # | Finding | Outcome |
|---|---|---|
| 1 | App liveness: a crash leaves `desktop.json` (macOS/Windows: "recording" forever); no `XDG_RUNTIME_DIR` → "not running" | Fixed: the app touches `desktop.json` every 10 s and writes `started`; older than 30 s = not running; Linux also checks `/proc/<pid>/comm` and `/run/user/<uid>` |
| 2 | start/stop block 45 s / 180 s, past common tool timeouts | Fixed: start waits 40 s, stop 50 s; a stop still saving is a success ("still saving") |
| 3 | `start_meeting` could confirm a meeting that the app deletes when the microphone fails | Fixed: confirmed only when the meeting is still there 3 s later (test) |
| 4 | Gemini line may need `--` | Not changed: checked with the installed Gemini CLI in a temporary HOME; it writes `args = ["--mcp"]` |
| 5 | The JSON snippet named Zed (Zed uses `context_servers`) | Fixed: Zed removed from that line and the README |
| 6 | `shellWord` double quotes expand `$`, `` ` ``, `\` | Fixed: single quotes (with `'\''`), double quotes only for `C:\` paths; checked in bash |
| 7 | `dup2` unchecked; the protocol fd could leak into child processes | Fixed: FD_CLOEXEC on the protocol copy, `/dev/null` when there is no stderr, no fd-1 ownership in the fallback |
| 8 | `get_meeting` said "recording" for an interrupted meeting | Fixed: the same state as the list (test) |
| 9 | No -32600 | Fixed: no method / not an object / empty batch (test) |
| 10 | `resources/list` cut at 500 without a cursor | Fixed: pages of 200 with `nextCursor` (test) |
| 11 | `transcribe_file` could download a model | Fixed: only downloaded models; else an error that says where to download |
| 12 | A status poll could flip the switch back | Fixed: not while its save is on its way |

Checked after the fixes: 118 unit tests pass; the real binary over stdio (private data, config
and runtime folders): handshake, every read tool, the refusal of start_meeting with the switch
off, transcribe_file (Small, 3.4 s), resources, the three liveness cases (fresh, dead pid, not
touched for 60 s), and a model that is not downloaded; engine logs (67 lines) go to stderr only.
Not checked: start/stop through the real app (`--meeting start --agent --title`), because that
needs the nested test session, which does not run yet in the headless labwc.
